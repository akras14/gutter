Gutter

A small macOS terminal app with a vertical tab sidebar, embedding libghostty (ghostty v1.3.1).

One window, one sidebar: every session is a full libghostty terminal surface (Metal rendering, PTY, input/IME come from ghostty's own Swift wrapper). Your existing Ghostty config drives the theme, font, working directory and keybinds.

Build & run

cd ~/projects/ak/gutter
./build.sh      # compiles app + vendored wrapper, links libghostty
./make-app.sh   # assembles dist/Gutter.app (bundles themes + shell integration + terminfo)
open dist/Gutter.app

build.sh does three things: compiles a tiny ObjC helper, compiles all Swift sources with swiftc (no Xcode project - the C API is bridged via ghostty's module.modulemap), and links against the static libghostty archives from the ghostty zig-cache.

Gotchas worth knowing

  • Archive padding: Xcode 26.6's libtool silently drops zig-built archive members that aren't 8-byte aligned. build.sh detects the broken fat archive and re-pads each zig-cache archive with Apple's ar before linking.
  • Resources: themes and shell integration are bundled at Contents/Resources/ghostty/ (found via the GHOSTTY_RESOURCES_DIR env var, set in main.swift), and terminfo is bundled at Contents/Resources/terminfo/ - spawned shells get TERM=xterm-ghostty plus a TERMINFO pointing there.
  • Keybind overrides: cmd+t=new_tab and cmd+9=goto_tab:9 are injected via a temp config file (see main.swift). Don't override command in config this way - repeated command keys append instead of replacing.
  • Rebuilding libghostty (rare): cd ~/projects/ak/ghostty && PATH="$HOME/projects/ak/.tooling/shim-bin:$PATH" zig build -Doptimize=ReleaseFast -Demit-macos-app=false -Dxcframework-target=native. The shim points zig's SDK detection at a shadow SDK whose tbds declare arm64-macos (macOS 26 SDKs dropped it; zig 0.15.2 needs it).

Run the app only as the bundled .app - the bare binary crashes because ghostty's logger force-unwraps Bundle.main.bundleIdentifier.

Postscript: the backspace bug

The one bug that survived the first pass: backspace wouldn't delete at the shell prompt. The core was parsing keys fine - it was packaging. The app bundled themes and shell-integration but not terminfo, so every spawned shell got TERM=xterm-ghostty with a TERMINFO pointing at a directory that didn't exist (and no system fallback). zsh's line editor silently lost its capabilities: it erased chars from its buffer but not from the screen. Fixed by bundling zig-out/share/terminfo like the official Ghostty.app does.

Credit: after GLM-5.3-Flash got stuck on this one, switching to Kimi K3 (moonshotai/kimi-k3) resolved it quickly - traced the failure to the core's TERMINFO wiring and fixed make-app.sh.
